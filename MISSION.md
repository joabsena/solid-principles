# Mission: SOLID Principles in Node.js with TypeScript

## Why
Broadening software engineering fundamentals. Moving from "I've heard of SOLID, can explain maybe one or two vaguely" to "I can explain, spot violations, and apply each principle instinctively on real TypeScript code." Not tied to a specific project or deadline — this is about building durable software design intuition.

## Success looks like
- Explain all 5 principles clearly in my own words, with a real TypeScript example per principle.
- Look at any Node/TypeScript class or module and identify which SOLID principle(s) it violates.
- Refactor a violating design into one that follows the principle — and explain *why* the new version is better.
- Know when *not* to apply a principle (dogmatism vs pragmatism).

## Constraints
- **Language**: TypeScript with Node.js only. All examples, exercises, and demos in the user's stack.
- **Structure**: Each lesson = one principle, self-contained HTML with explanation, diagram, code exercise, and recall quiz.
- **Pacing**: Lessons build on each other. Later lessons interleave earlier principles to reinforce.

## Out of scope
- Functional programming alternatives to SOLID.
- SOLID in other languages (Java, C#, Python) — mention only in passing for historical context.
- Domain-Driven Design, hexagonal architecture, or other architectural patterns (except where a principle naturally links).
