Liskov Substitution

The subtype must keep the behavioral promises clients rely on.

Review question: If I replace this implementation with another subtype, do all existing clients still get behavior consistent with the contract?

Contract rules of thumb

  • A subtype must not require more from callers (no stronger preconditions).
  • A subtype must not promise less to callers (no weaker postconditions).
  • A subtype must preserve the invariants clients expect.
  • Exceptions and side effects are part of behavior too.

Useful diagnosis

  1. Write down what the base type promises.
  2. Write a client that depends only on that promise.
  3. Substitute each implementation and inspect the result.
  4. If a subtype needs a special case, reconsider the contract.
Remember: this is about behavioral subtyping. It applies to class inheritance, interface implementations, and structural TypeScript types. TypeScript can check shape compatibility; it cannot prove every runtime promise.
