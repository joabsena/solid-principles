SRP in functional TypeScript

Separate change ownership, not necessarily classes.

Core idea: a function or module has one responsibility when one actor owns the reason for changing it. Functional style changes the mechanism—composition instead of objects—but not the design question.
ResponsibilityFunctional shapeTypical owner
Business rule(input) => output, pureProduct / domain
Persistencesave: (value) => Promise<void>Data / platform
Notificationnotify: (to, message) => Promise<void>Messaging / marketing
Observabilityaudit: (event, data) => voidSRE / platform

Review checklist

  1. Which lines are pure business rules?
  2. Which lines talk to the outside world?
  3. Which actor would request each kind of change?
  4. Can effects be passed in at the composition boundary?
