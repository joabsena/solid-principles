The question each principle helps you ask in a TypeScript code review.

LetterAskSmellTypical move
SWho asks for this class to change?Several actors own one moduleSeparate by actor
OWhat behavior will vary next?Stable code grows conditionalsPut variation behind a contract
LCan every subtype keep the promises?Subtype needs exceptions or surprisesRedesign the abstraction
IDoes this client need every method?Implementations throw or fake methodsSplit interfaces by client need
DWho owns the policy/detail boundary?High-level policy constructs concrete toolsDepend on abstractions and inject details
Pragmatic OCP test: name the expected change axis. If adding a new case repeatedly edits the same stable coordinator, introduce an extension point there. If the variation is unlikely, a small conditional may be clearer.
