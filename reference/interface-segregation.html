Interface Segregation

Shape a contract around the needs of its clients.

Review question: Does this client depend on operations it neither calls nor needs to know about?

Smells

  • Implementations throw “not supported” from required methods.
  • Implementations return dummy values just to satisfy an interface.
  • A small client needs a large mock or fake to test one operation.
  • Unrelated consumers change together when an interface changes.

Refactoring move

  1. List the operations each client actually needs.
  2. Group operations that serve a cohesive client role or capability.
  3. Give each client the narrow contract it depends on.
  4. Let a rich implementation implement several small contracts when appropriate.
Pragmatic limit: small does not mean one interface per method. Split when clients or implementations have different needs; keep related operations together.
